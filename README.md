# سامانهٔ ضد چندپارگی: طراحی، پیاده‌سازی و عیب‌زدایی یک پردازشگر متن فارسی

## چکیده
امروزه پردازش متون فارسی با چالش‌هایی چون وجود نویسه‌های عربی، چندپارگی نوشتاری و نبود معیارهای سنجش کیفیت متن روبه‌روست. در این مقاله سامانه‌ای تحت وب مبتنی بر Flask معرفی می‌شود که سه خدمت اصلی «نطق مصطلح» (جایگزینی نویسه‌های عربی با فارسی)، «میزان‌رو» (تحلیل کیفیت و خوانایی) و «ضد چندپارگی» (حذف فاصله‌های زائد و یکپارچه‌سازی متن) را ارائه می‌دهد. ضمن تشریح معماری و منطق پردازشی، به فرایند عیب‌زدایی پروژه شامل شناسایی و رفع هفت باگ کلیدی پرداخته شده است. نتایج تجربی بر روی نمونه‌های واقعی کارکرد صحیح هر سه ماژول را تأیید می‌کنند.

**کلیدواژه‌ها**: پردازش زبان فارسی، ضد چندپارگی، نطق مصطلح، میزان‌رو، Flask، عیب‌زدایی نرم‌افزار

---

## ۱. مقدمه
زبان فارسی در محیط‌های دیجیتال پیوسته با ناهماهنگی‌های املایی، نفوذ نویسه‌های عربی (مانند «ي» و «ك») و فاصله‌گذاری‌های نادرست روبه‌روست. این مسائل نه تنها خوانایی متن را کاهش می‌دهند، بلکه در کاربردهای پردازش زبان طبیعی (NLP) نیز خطا ایجاد می‌کنند.

پروژهٔ «سامانهٔ ضد چندپارگی» (Anti-Fragmentation System) با هدف مقابله با این مشکلات طراحی شده و سه خدمت اصلی را در قالب یک API وب ارائه می‌کند. در ادامهٔ مقاله، ابتدا معماری سامانه، سپس هر یک از ماژول‌ها و در نهایت فرایند کشف و رفع باگ‌های موجود در نسخهٔ اولیه شرح داده می‌شود.

---

## ۲. معماری کلی سامانه
سامانه یک برنامهٔ Flask است که روی پورت ۵۰۰۰ اجرا می‌شود و دارای ساختار زیر می‌باشد:

```

Anti-Fragmentation-System/
├── main.py                  # نقطهٔ ورود اصلی (Flask app)
├── text_processor/          # بستهٔ پردازشگرهای اصلی
│   ├── init.py
│   ├── nataq.py             # کلاس NataqProcessor
│   ├── mizanro.py           # کلاس MizanroAnalyzer
│   └── anti_frag.py         # کلاس AntiFragmentation
├── templates/               # قالب‌های HTML
├── static/                  # فایل‌های استاتیک (CSS, JS)
└── run_simple.py            # نسخهٔ ساده برای تست سریع

```

### ۲.۱ مسیرهای API
| مسیر | روش | عملکرد |
|------|-----|---------|
| `/nataq` | GET, POST | نطق مصطلح |
| `/mizanro` | GET, POST | میزان‌رو |
| `/anti_fragmentation` | GET, POST | ضد چندپارگی |
| `/health` | GET | سلامت سرویس |

## ۳. ماژول نخست: نطق مصطلح (Nataq Processor)
**هدف**: جایگزینی نویسه‌های عربی «ي» و «ك» با معادل‌های فارسی «ی» و «ک» و نرمال‌سازی نیم‌فاصله‌ها.

**ورودی**: یک رشتهٔ متنی JSON با کلید `text`.

**خروجی**:
```json
{
  "success": true,
  "processed_text": "کتابی درباره‌ی شعر"
}
```

منطق پردازشی (کلاس NataqProcessor در nataq.py):

1. شناسایی و جایگزینی «ي» (U+064A) با «ی» (U+06CC).
2. جایگزینی «ك» (U+0643) با «ک» (U+06A9).
3. نرمال‌سازی فواصل و نیم‌فاصله‌ها.

نمونهٔ تجربی:

```bash
curl -X POST http://127.0.0.1:5000/nataq \
  -H "Content-Type: application/json" \
  -d '{"text":"كتابي درباره‌ي شعر"}'
# پاسخ: "کتابی درباره‌ی شعر"
```

۴. ماژول دوم: میزان‌رو (Mizanro Analyzer)

هدف: تحلیل کیفیت متن شامل شمارش کلمات، جملات، محاسبهٔ امتیاز پیچیدگی و تنوع واژگانی.

کلاس: MizanroAnalyzer (mizanro.py)

خروجی نمونه:

```json
{
  "success": true,
  "analysis": {
    "word_count": 8,
    "sentence_count": 2,
    "unique_words": 6,
    "avg_sentence_length": 4.0,
    "lexical_diversity": 0.75,
    "complexity_score": 42
  }
}
```

شاخص‌ها:

· تعداد کلمات / جملات: شمارش با split.
· تنوع واژگانی: نسبت واژه‌های یکتا به کل واژه‌ها.
· میانگین طول جمله: نسبت کلمات به جملات.
· امتیاز پیچیدگی: ترکیبی وزنی از طول جملات و تنوع واژگانی (هرچه پایین‌تر، متن روان‌تر).

۵. ماژول سوم: ضد چندپارگی (Anti-Fragmentation)

هدف: کاهش چندپارگی نوشتاری از طریق حذف فاصله‌های اضافی و خطوط خالی متوالی و ارائهٔ امتیاز قبل و بعد از بهینه‌سازی.

کلاس: AntiFragmentation (anti_frag.py)

متد اصلی: process(text) → متن بهینه‌شده را در یک دیکشنری برمی‌گرداند.

متد کمکی: _calculate_fragmentation(text) → امتیاز چندپارگی را بر اساس معیارهای زیر محاسبه می‌کند:

· فاصله‌های دوتایی ('  ') → ضریب ۱
· فاصله‌های سه‌تایی ('   ') → ضریب ۳
· خطوط خالی متوالی ('\n\n') → ضریب ۲

فرمول:

```
score = (count('  ') * 1) + (count('   ') * 3) + (count('\n\n') * 2)
```

درصد بهبود:

```
improvement% = (1 - score_after/score_before) * 100
```

نمونهٔ تجربی:

```bash
curl -X POST http://127.0.0.1:5000/anti_fragmentation \
  -H "Content-Type: application/json" \
  -d '{"text":"این   یک    متن        شلوغ است."}'
```

پاسخ:

```json
{
  "success": true,
  "original_text": "این   یک    متن        شلوغ است.",
  "processed_text": "این یک متن شلوغ است.",
  "fragmentation_score_before": 26,
  "fragmentation_score_after": 0,
  "improvement_percentage": 100.0
}
```

۶. عیب‌زدایی (Debugging): شناسایی و رفع ۷ باگ اصلی

در بررسی اولیهٔ کد منبع، چندین باگ ساختاری و منطقی شناسایی و به‌ترتیب زیر اصلاح شدند:

🐞 باگ ۱: محاسبهٔ اشتباه fragmentation score

· مکان: text_processor/anti_frag.py متد _calculate_fragmentation
· مشکل: فاصلهٔ خالی دو بار با ضرایب ۲ و ۳ محاسبه می‌شد.
· رفع: اصلاح منطق محاسبات و تفکیک صحیح ضرایب برای فاصله‌ها و خطوط جدید.

🐞 باگ ۲: ناسازگاری پورت‌های اجرایی

· مشکل: main.py روی پورت ۵۰۰۰ و app_simple.py روی پورت ۵۰۰۱ تنظیم بود.
· رفع: هماهنگ‌سازی هر دو روی پورت ۵۰۰۰.

🐞 باگ ۳: الگوی import نامناسب در __init__.py

· مشکل: وارد کردن نمونه‌ها به‌جای کلاس‌ها که می‌توانست باعث ImportError شود.
· رفع: اصلاح __init__.py به وارد کردن مستقیم کلاس‌ها:

```python
from .nataq import NataqProcessor
from .mizanro import MizanroAnalyzer
from .anti_frag import AntiFragmentation
```

🐞 باگ ۴: پیام‌های خطای فارسی در APIها

· مشکل: بازگشت رشته‌های خطای فارسی که برای کلاینت‌های استاندارد نامناسب است.
· رفع: جایگزینی با ساختار استاندارد انگلیسی:

```python
jsonify({"error": "Internal Server Error", "details": str(e)}), 500
```

🐞 باگ ۵: عدم پذیرش متد POST (405 Method Not Allowed)

· مشکل: مسیرها فقط GET را قبول می‌کردند.
· رفع: افزودن methods=['GET', 'POST'] به دکوراتورهای مسیر.

🐞 باگ ۶: پاسخ HTML به‌جای JSON برای درخواست‌های POST

· مشکل: توابع مسیر صرفاً قالب HTML برمی‌گرداندند و منطق پردازش POST پیاده‌سازی نشده بود.
· رفع: افزودن شرط if request.method == 'POST': و فراخوانی کلاس‌های پردازشگر اصلی.

🐞 باگ ۷: خطای AttributeError: 'dict' object has no attribute 'count'

· مکان: main.py خط ۵۸ و به تبع آن _calculate_fragmentation
· علت: متد process از کلاس AntiFragmentation یک دیکشنری بازمی‌گرداند، اما کد مقدار بازگشتی را مستقیماً به تابع _calculate_fragmentation که نیاز به رشته دارد، پاس می‌داد.
· رفع: استخراج کلید processed_text از دیکشنری پیش از ارسال به تابع محاسباتی.

پس از رفع تمام باگ‌ها، هر سه سرویس با ۱۰۰٪ موفقیت بر روی نمونه‌های زیر تست شدند:

۸. جمع‌بندی و کارهای آینده

سامانهٔ ضد چندپارگی به‌عنوان یک ابزار سبک اما مؤثر برای استانداردسازی متون فارسی ارائه شد. در فرایند عیب‌زدایی، ۷ باگ در سطوح مختلف (منطق محاسباتی، ساختار درخواست‌ها، مدیریت خطا و...) شناسایی و رفع گردید. پروژه اکنون کاملاً عملیاتی است و می‌توان از آن در پشت یک وب‌سرویس یا به‌عنوان کتابخانهٔ مستقل پردازش متن استفاده کرد.

پیشنهادها برای توسعهٔ آتی:

· افزودن پشتیبانی از احراز هویت API
· ساخت ماژول تشخیص خودکار زبان و نویسه‌گردانی
· ارائهٔ واسط خط فرمان (CLI) علاوه بر REST
· یکپارچه‌سازی کامل فایل‌های استاتیک (Bootstrap, لوگو) برای بهبود ظاهر
